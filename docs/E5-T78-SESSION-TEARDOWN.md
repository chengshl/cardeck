# E5 T78 · 车机会话主动退出修复（L3隔离）

## 用户已观察事实
- T22仅视频成功建立时：HFP/A2DP未被App主动拆，但普通音乐可能暂停。此问题与视频流退出独立，**此版不处理T26资源声明或CarPlay音频协议**。
- 手机主动断开后车机仍显示CarPlay占用，并与后续0x4300 ACK109 / 0x4301迟到或不达的重连故障同时出现。有关联可能，但根因未证。
- 未进入正式会话的“连接中取消”可能令车机普通蓝牙重连；此版不承诺已解决，先保证快速取消不冒发无效TEARDOWN。

## 本轮代码
- 基于签名E5#34分支`36e5f600`（保留T22/详细诊断/自动更新），只修改`SessionController`退出路径与其纯状态测试。
- 记录成功屏幕RECORD对应的AirPlayClient identity；`disconnect()`在屏幕视频确实运行、客户端与该已RECORD会话相同时，后台发送原有`tryTeardownBuickScreen(displayUuid)`后退出；仅B233会发TEARDOWN，非B233拒发且继续本地清理。
- UI线程不网络阻塞；900ms RTSP应答 + 1700ms独立清理兜底；AtomicBoolean一次性清理、退出中拒绝新连接、防视频结束迟到回调清理未来会话。
- 没有更改T39快速重试/ACK109、RFCOMM业务消息、视频编码/触摸、音频资源claims。
- **风险**：车机可能没有处理该RTSP TEARDOWN，或断链自动重连仍失败；不可仅用手机日志的本地清理声明代表车机已退出。

## 验收与回退
- 先备份E5手机本地诊断日志，同包名同签名更高versionCode直接覆盖（低版不能无损覆盖回退）。
- 停车实车至少3轮成功建立画面→手动断开→车机返回原生UI→HFP/A2DP保持→能够重新连接，记录每轮时间、T78日志与实际车机行为。连接中取消须稳定快速退出、不闪退；若普通蓝牙仍断需与车机侧ACL拆链区分。独立取证程序不更改。
- 本轮仅 CI 与发行签名成功，尚需手机验收；试验结果不能直接整体合入稳定`Buick-E5`。
