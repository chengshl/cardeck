本次更新：重构「别克设置 → 软件更新」为统一深色页面，解决原版粉色弹窗文字换行、选项不直观及自动检查渠道与人工选择脱节的问题。

- 「别克设置」只保留一个「软件更新」入口；删除与其重复的「自动检查更新」一级菜单。
- 新页面直接显示「正式分支」「试验分支」两张清晰可点选的卡片，附适用范围说明；不再让用户每次进入时先面对宽度不足的粉色原生选择弹窗。
- 选中渠道立即持久保存，仅影响当前APK自身数据，不与Buick-E5、Buick-main等独立包共享；首次默认正式分支。
- 自动检查更新开关移入同一软件更新页面。开启后进入别克设置检查的是**当前已选渠道**：正式查原独立 `buick-test-latest`，试验查归属于Buick-Test的受限 `exp-buick-test-*` 预发布。自动检查只提示有更新，下载安装仍需人工确认。
- 「检查所选分支更新」始终遵守上述渠道；选择试验分支时额外显示「查看试验分支历史安装包」，供手动选择任意允许升级的实验版本。
- 更新与实验对话框切换为AppCompat暗色组件，修正旧文案的反斜杠n显示异常；软件更新新页面使用纵向排版和多行文字，菜单说明允许两行显示。
- 版本详情继续显示来源分支、APK版本、更新说明及构建完成北京时间。旧版本无buildAt时只显示标明来源的版本时间，不伪称构建时间。
- 维持包名、签名、SHA256、来源与versionCode校验：实验高版本不能强行降级为旧正式版；三个正式通道/缓存互不混用。
- 与本功能无关的CarPlay视频、触控、AAC音频、Shizuku虚拟屏和T75诊断逻辑均不改动。软件更新CI成功不表示音频20秒断连已解决。
- 需求和逐次提交/构建见GitHub #17，项目总清单见 #12。
交接补充（2026-10-26）：`docs/BRANCH-EXPERIMENT-UPDATE-CHANNELS.md` 已同步修改为最新用户约定。重点是用户选中的正式/试验渠道必须同时控制手动检查和自动检查，不再采用过去“自动检查固定正式”的旧规则。本APK安装后需验证真实页面的选项文字自然换行、选择状态重进仍保留，及按钮/自动检查是否遵守渠道；编译验证与实机验收分开记录。

细节修正：自动检查开关不仅依赖颜色/滑块位置，统一软件更新页增加明确的“状态：已开启/已关闭”文字，关闭态与开启态使用不同颜色，便于索尼手机暗色屏识别。之前三分支构建曾因 ScrollView 的 Kotlin 属性名称及 Buick-Test 中文说明门禁失败，已修正并重新验证。最终 CI 状态以本次提交构建为准。
