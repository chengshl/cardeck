# Buick E5 T64 · UI transition and map task reuse — 2026-10-26

Source: 24-second private in-car video and Gateway's anonymized T63 app logs. Original footage, visible map content, physical/device identifiers and raw logs are not uploaded.

## What was observed
- Video shows hard cuts between Dashboard, Grid and apps. T63 app logs show healthy touch delivery and ongoing video/RTSP; keepAlive observed fps=28, not proof of consistent frame pacing.
- Activity mode logging repeatedly switches Desktop ↔ Dashboard and resizes map between 1573x520 and 843x444, potentially triggering Android relayout.
- GridActivity.applyDashboardMode used setCurrentItem(...,false); onPageSelected caused notifyItemChanged on every Grid entry, even with no dimension change.
- syncDashboard(true) called ensureMapTask for every entry, issuing am start even if the same default map was already running.
- launchMapOnMapDisplay always used MULTIPLE_TASK and cleared *the package about to be opened* for non-default maps, defeating task reuse.
- No newly uploaded system source for the current test window. This does not prove Android system had no issues.

## T64 narrow improvements
- [x] Native smooth ViewPager2 page transition when measured and idle; retain immediate fallback at startup / when another gesture is ongoing.
- [x] Keep reflow only on actual pager bounds change; eliminate full page rebinding on every switch.
- [x] Cache last successful map package only within one car session, so returning to Dashboard with the same map avoids redundant am start.
- [x] Reopening the same map in that session prefers normal NEW_TASK without MULTIPLE_TASK and never first removes the requested map's existing task.
- [x] Guard asynchronous dashboard entry against stale mode before starting map work.
