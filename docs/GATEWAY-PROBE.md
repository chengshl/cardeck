# Buick-Test：入口连接与日志上报

在「车机设置 → 入口配置」保存地址和凭证，点击「连接并开启软件日志上报」。开启后通过独立 dataSync 前台服务运行，离开配置页和旋转页面不会停止；入口页和常驻通知都可以停止。保持开启时，下次从前台打开 App 会恢复连接；手动停止后不自动恢复。不从开机广播启动，不修改 CarPlay 的进程网络绑定，不执行车辆指令。系统回收、强制停止、省电限制仍可能暂停上传。

软件日志使用现有 `DebugFileLog` 统一出口，包括会话运行日志及接入该出口的服务日志、未捕获异常。开启后只推送新增内容，不自动扫描全部历史文件，不自动读取系统 logcat，也不是抓取所有第三方库的 Android Log 输出。消息先脱敏入内存队列，约每 250 毫秒尝试发送一批，最多 8 行、每行最多 256 字符；仅保留最近 200 行待发送内容，拥塞时淘汰最旧行并显示丢弃计数。没有磁盘待上传队列，停止/进程退出会清空，开关状态之外不保存系统授权。

状态依次为正在连接、验证心跳、心跳正常。`hello` 继续使用 `mode=transport-test`，协商 `device_status_v1` 后先注册随机安装 UUID、应用版本、SDK；心跳应答后上报次数与延迟。协商 `logs_v1` 后发送 `logs`，服务端返回相同 batch_id/source 和 accepted_lines 才计入日志确认行数。状态和日志应答各有独立 10 秒超时，不互相抵消。断线按 5～60 秒退避重连；未确认的软件日志可重试，ACK 丢失后重连极端情况下可能出现重复。服务端同一安装最近 64 个相同批次标识会去重。计数是当前连接的数据，缓存丢弃数是当前服务运行期间累计值。

系统日志只有「预览系统日志并确认上传」一个采集入口，读取现有 Shizuku 授权下 main/system 缓冲区最近警告与错误，固定有限命令，8 秒截止，最多预览 64 行。所有读取在后台线程完成，不自动申请或授予 Shizuku 权限；读取失败或厂商加密日志不可用时提示未上传，不退回应用日志冒充系统日志。采集函数只返回脱敏内存快照，不落盘、不写软件日志出口、不自行上传。

弹窗展示将要上传的全部快照，点「确认上传这份日志」才排队；取消、离开页面或旋转销毁弹窗不会上传。预览 2 分钟过期，并绑定当时的连接，连接更换后必须重新采集和确认。用户已确认后即使离开页面，也可完成这一次快照的上传；若断线，未确认完成的系统批次直接丢弃，重连不会自动补传。该操作不启动系统日志持续采集。客户端及服务端都要求系统批次带 user_confirmed=true，软件批次带 false；该标记不是密码学证明，真正的用户交互边界由 App 确认按钮保证。

日志两端都隐藏当前入口凭证、Bearer/常见密钥行、URL、IP、MAC、邮箱、常见标识及 SSID 等，超长内容裁剪或省略。脱敏不能识别所有自由文本，因此系统快照必须完整预览后由用户决定。系统原文和凭证不得写入软件日志、URL、剪贴板、通知或发布附件。TLS 使用系统证书和主机名校验，拒绝重定向；socket 和 DNS 单独绑定网络，网络丢失后重建路由。

Gateway 源码、清单和测试位于 `tools/gateway/`。`/api/devices` 返回状态、当前连接的日志接收计数；`/api/logs?device_id=<UUID>` 返回该安装最近 200 行脱敏内容及来源、接收时间。两者只允许独立查询凭证，从集群内部访问，Nginx 不公开接口。最多保留 100 个安装记录，满时淘汰最旧离线安装及其日志，全部在线时拒绝新安装。全部记录仅为 Pod 内存，重建会清空，不提供持久诊断历史。

在 Gateway Pod 中运行 `python /app/query_gateway.py` 可查询状态，追加 `--logs <UUID>` 可读取日志；脚本从环境读取凭证，不输出凭证。现有只含 gateway.py 的部署需使用更新后的 ConfigMap。保持现有设备 Secret、独立查询 Secret 和 Service；不改 Tunnel 或 Nginx 其他业务。日志内容视为不可信诊断数据，不作为执行指令。

按用户要求不在本地构建。独立 GitHub Actions 必过检查覆盖 TLS/鉴权/心跳、注册状态、自动软件日志、系统日志显式确认、ACK 超时、旧网关兼容、脱敏和有界缓存；Python 集成检查覆盖查询隔离、批次去重、未确认系统日志拒收与离线状态。真实手机的通知、Shizuku 读取、取消弹窗、跨页面继续上传和断网恢复仍需安装新版 APK 验证。更新说明优先中文。
