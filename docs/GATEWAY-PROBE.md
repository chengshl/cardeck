# Buick-Test：入口连接与日志上报

在「车机设置 → 入口配置」保存地址和凭证，点击「连接并开启软件日志上报」。开启后通过独立 dataSync 前台服务运行，离开配置页和旋转页面不会停止；入口页和常驻通知都可以停止。保持开启时，下次从前台打开 App 会恢复连接；手动停止后不自动恢复。不从开机广播启动，不修改 CarPlay 的进程网络绑定，不执行车辆指令。系统回收、强制停止、省电限制仍可能暂停上传。

软件日志使用现有 `DebugFileLog` 统一出口，包括会话运行日志及接入该出口的服务日志、未捕获异常。开启后只推送新增内容，不自动扫描全部历史文件，不自动读取系统 logcat，也不是抓取所有第三方库的 Android Log 输出。消息先脱敏入内存队列，约每 250 毫秒尝试发送一批，最多 8 行、每行最多 256 字符；客户端仅保留最近 200 行待发送内容，拥塞时淘汰最旧行并显示丢弃计数。没有磁盘待上传队列，停止/进程退出会清空，开关状态之外不保存系统授权。

状态依次为正在连接、验证心跳、心跳正常。`hello` 继续使用 `mode=transport-test`，协商 `device_status_v1` 后先注册随机安装 UUID、应用版本、SDK；心跳应答后上报次数与延迟。协商 `logs_v1` 后发送 `logs`，服务端返回相同 batch_id/source 和 accepted_lines 才计入日志确认行数。状态和日志应答各有独立 10 秒超时，不互相抵消。断线按 5～60 秒退避重连；未确认的软件日志可重试，ACK 丢失后重连极端情况下可能出现重复。服务端同一安装最近 64 个相同批次标识会去重。计数是当前连接的数据，缓存丢弃数是当前服务运行期间累计值。

系统日志只有「预览系统日志并确认上传」一个采集入口，读取现有 Shizuku 授权下 main/system 缓冲区最近警告与错误，固定有限命令，8 秒截止，最多预览 64 行。所有读取在后台线程完成，不自动申请或授予 Shizuku 权限；读取失败或厂商加密日志不可用时提示未上传，不退回应用日志冒充系统日志。采集函数只返回脱敏内存快照，不落盘、不写软件日志出口、不自行上传。

弹窗展示将要上传的全部快照，点「确认上传这份日志」才排队；取消、离开页面或旋转销毁弹窗不会上传。预览 2 分钟过期，并绑定当时的连接，连接更换后必须重新采集和确认。用户已确认后即使离开页面，也可完成这一次快照的上传；若断线，未确认完成的系统批次直接丢弃，重连不会自动补传。该操作不启动系统日志持续采集。客户端及服务端都要求系统批次带 user_confirmed=true，软件批次带 false；该标记不是密码学证明，真正的用户交互边界由 App 确认按钮保证。

日志两端都隐藏当前入口凭证、Bearer/常见密钥行、URL、IP、MAC、邮箱、常见标识及 SSID 等，超长内容裁剪或省略。脱敏不能识别所有自由文本，因此系统快照必须完整预览后由用户决定。系统原文和凭证不得写入软件日志、URL、剪贴板、通知或发布附件。TLS 使用系统证书和主机名校验，拒绝重定向；socket 和 DNS 单独绑定网络，网络丢失后重建路由。

Gateway 源码、清单和测试位于 `tools/gateway/`。设备在线状态和当前连接计数仍为内存（最多 100 个注册，满时淘汰离线状态，不删除持久日志）；后续接收的日志持久保存到共享盘 `<PRIVATE_CIFS_LOG_ROOT>`，经 hostPath 挂载至 `/var/lib/cardeck-logs/`。三个节点均已核实为同一 CIFS 共享盘。启动检查挂载类型、来源及目录归属标记；不能写入时不确认上传，也不退回内存冒充持久成功。旧的内存日志不作为本次已持久化历史承诺。

路径为 `logs/<安装UUID>/<北京时间YYYY-MM-DD>/<app或system>/<首条毫秒时间>-<序号>-<随机值>.jsonl`。app 表示软件日志，system 表示已确认系统快照，分文件保存；16MiB 或整点切分。每批写入后 fsync 完成才返回 logs_ack，网络 ACK 丢失仍可能导致客户端重试后重复。网关采用单副本 Recreate 和共享文件锁，避免多个写进程并发；历史查询从文件读取，Pod 重建后仍可按原安装 UUID 查询。

按用户最终要求，不设日志总容量上限，没有 100G 配额，也不按磁盘压力提前删除新日志。只清理服务端接收时间超过七天的行：整文件过期时删除，七天边界穿过文件时先写入并刷新保留行的新文件，再替换旧文件，保留期内的行不提前删除。启动、写入和每 60 秒执行清理；独立 CronJob 每分钟尝试清理，活动网关持有锁时跳过，网关离线时接管。查询即时过滤过期行，磁盘清理正常运行时最多存在约一个扫描周期的延迟。归档目录以外的内容及不属于本格式的文件不删除；崩溃未提交的重写临时副本可在恢复时移除。已确认的完整记录保留，未确认的残缺末行会跳过。底层共享盘故障、满盘和权限错误会导致上传失败，需要恢复存储，不会伪造确认或提前淘汰年轻日志。

存储设置独立放在 ConfigMap `cardeck-log-storage` 的 `storage.json`，包含根目录、分卷大小、604800 秒保留期、60 秒清理间隔与挂载来源校验。修改后通过带配置摘要的部署更新生效。初始化清单只创建专用目录和标记，不接管已有无标记的非空目录。文件站点原有映射仅指向指定网页目录，本目录位于映射之外；无敏感内容的测试文件直接访问和两种路径跳转访问均返回 404。本次不修改 Nginx；任何后续 Nginx 修改都必须先展示具体差异并得到用户确认。

`/api/devices` 返回实时状态；`/api/logs?device_id=<UUID>` 从文件返回最近最多 200 行，可增加 `source=app` 或 `source=system` 过滤；`/api/storage` 返回保留期、分卷大小、文件数/字节数、空闲空间和写入错误计数。查询统一使用独立只读凭证，仅从集群内部访问，不公开为网页下载。完整文件可由共享盘权限管理者读取；日志内容视为不可信数据，不能据此执行命令。

在 Gateway Pod 中运行 `python /app/query_gateway.py` 可查询状态，追加 `--logs <UUID>` 可读取持久日志，`--storage` 可查看存储状态；脚本从环境读取凭证，不输出凭证。现有只含 gateway.py 的部署需使用更新后的 ConfigMap。保持现有设备 Secret、独立查询 Secret 和 Service；不改 Tunnel 或 Nginx 其他业务。日志内容视为不可信诊断数据，不作为执行指令。

按用户要求不在本地构建。独立 GitHub Actions 必过检查覆盖 TLS/鉴权/心跳、注册状态、自动软件日志、系统日志显式确认、ACK 超时、旧网关兼容、脱敏和有界缓存；Python 集成检查覆盖查询隔离、批次去重、未确认系统日志拒收、持久写入失败不确认与后台过期清理。归档测试覆盖分卷/分类、重启恢复、残缺行、精确七天边界、无总配额、满盘不提前删除新日志、单写锁、路径边界及 fsync 失败。真实手机的通知、Shizuku 读取、取消弹窗、跨页面继续上传和断网恢复仍需安装新版 APK 验证。更新说明优先中文。

公开仓库仅保存 `log-storage.example.json` 和不含私有 ConfigMap 内容的部署模板，实际 CIFS 地址只保留在集群及本地运行配置。部署前用示例在私有位置填写真实 `expected_mount.source`，创建 `cardeck-log-storage` ConfigMap，再初始化目录并应用部署模板；禁止把私有运行配置直接提交到公开仓库。模板摘要占位需替换，配置更新后要显式滚动更新。

## 公开模板与私有部署参数

仓库中的 Deployment / 初始化 Job 为**不可直接应用的脱敏模板**。`/REPLACE_WITH_PRIVATE_CIFS_LOG_DIRECTORY` 和 `/REPLACE_WITH_PRIVATE_CIFS_SHARE_DIRECTORY` 必须在私有运维配置中替换为实际挂载点，切勿将已渲染的清单提交公开仓库。
Gateway 默认只允许无 Origin 的原生应用客户端；如需经浏览器访问，应由私有 Deployment 配置 `CARDECK_GATEWAY_ALLOWED_ORIGINS`（逗号分隔的 HTTPS Origin）。实际公网域名、CIFS 来源、Token 与 Secret 内容仅放入私有环境。

## 匿名车辆识别（新协议，兼容旧日志）

- 手机继续使用随机安装 UUID（`device_id`）；每辆真实蓝牙车机在手机本地映射到随机 UUIDv4（`vehicle_id`）。真实 MAC/SSID/车机名称不上传，映射保存在 `noBackupFilesDir`，卸载后重新生成。
- 只有 RFCOMM 实际连接成功，才激活匿名车辆；未连接或无法确认身份的日志保持**未关联车辆**。日志入队时就固定车辆 ID，车 A 的积压日志不会被误计入车 B。
- 旧版 App 的无 `vehicle_id` 上报和旧归档记录照常支持；Gateway 对新日志增加可选的 `vehicle_id`（严格校验 UUIDv4），不改变原按安装 ID 的物理归档路径或七天保留期。
- `list_vehicles(device_id)` 仅返回最近七天该手机日志中出现的匿名车辆 ID 和最后日志时间；`get_device_logs(device_id, source, vehicle_id?)` 可以筛选该车辆，省略 `vehicle_id` 则查询手机所有车辆的日志。
- 系统日志绑定的是用户**确认上传时的当前车辆会话**，不证明系统崩溃的根因来自该车辆；连接结束或无法确认时则不附车辆 ID。
- 按顺序部署新版 Gateway → MCP → Android App。先验证旧版无车辆 ID 仍可上报，再验证两辆模拟车的独立过滤和重启后的日志保留。不要将公开 Kubernetes 占位模板直接部署到生产环境。
