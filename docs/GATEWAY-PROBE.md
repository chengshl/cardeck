# Buick-Test：WSS 入口连接测试

在「车机设置 → 入口配置」填写服务地址和入口凭证，先保存，再点击「连接测试」。测试只使用已保存的配置；修改输入后必须重新保存，避免测试到旧地址或旧凭证。

状态依次为：正在连接 → 已连接、正在验证心跳 → 心跳正常。心跳正常会显示应答次数及最近一次 JSON 心跳往返时间。鉴权失败、证书验证失败、协议不匹配、HTTP 错误、网络中断和心跳超时分别显示原因，不回显服务器消息、凭证或异常原文。

本实现对接测试 Gateway 的 `hello(mode=transport-test)` 与 `heartbeat/heartbeat_ack` 协议。JSON 心跳收到应答后间隔 10 秒发送下一次，应答超时为 10 秒；传输层同时由 OkHttp 处理 WebSocket ping/pong。仅握手成功不会显示心跳正常。

当 hello 的 capabilities 包含 `device_status_v1` 时，App 先注册随机安装 UUID、应用版本和 Android SDK 版本；每次心跳成功后上报已确认次数和往返毫秒数。只有收到 `status_ack` 才增加页面的状态上报次数；注册或状态应答超时会结束测试。旧 Gateway 不声明能力时仍只测心跳。安装 UUID 位于 noBackupFilesDir，不读取 Android ID、序列号、MAC、位置或车辆数据。

Gateway 源码和部署清单位于 `tools/gateway/`。`/api/devices` 使用单独的只读凭证，仅从集群内部访问，现有 Nginx 不公开该路径。查询返回应用版本、SDK、在线状态、最近上报时间和心跳摘要；不返回入口凭证、IP 或原始日志。`online` 表示连接尚未关闭或超时，并非车辆业务在线。最多保存 100 个安装记录，满时淘汰最旧离线记录；全部在线时拒绝新注册。记录仅保留于当前 Pod 内存，Pod 更换会清空，尚非持久诊断历史。查询脚本在 Pod 内运行，凭证从环境读取，不写入脚本或输出。

「断开测试」、离开页面或旋转重建页面会结束测试并回收 socket、定时器与网络回调，不会在后台自动重连。再次测试需要手动点击。配置保存状态与连接测试状态分别显示。

互联网线路只绑定测试 socket 和 DNS，不修改 CarPlay 的进程网络绑定；选中网络丢失时立即结束测试。仍需在实际手机上分别验证 VPN、移动数据及连接车机热点时的路由行为。

使用系统 TLS 证书和主机名校验，不跟随 HTTP 重定向，也不把凭证写入 URL、日志或构建附件。本功能不执行车辆指令，不转发设备日志，不代表实车业务链路已接入。

云端必过测试 `GatewayProbeTest` 覆盖：TLS 下 Bearer 鉴权与连续心跳、401 拒绝、重定向拒绝、无应答超时、缺少/错误 hello、不可信证书、网络丢失和主动断开后的回调收口。按用户要求不在本地编译；实际执行结果以本次 GitHub Actions 为准。

新增云端硬性检查覆盖注册白名单、状态确认后计数、缺失状态确认超时，以及旧网关兼容；Gateway 集成检查覆盖读写凭证隔离、注册、上报查询、字段校验和离线标记。模拟端验证不代表手机已升级；需安装新 APK 并重新连接，查到对应应用版本及上报次数后才能确认手机数据链路。
