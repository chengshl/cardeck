# 统一长日志 v2（源码候选）

目标是 Store 和 CarDeck 都完整传送长日志。CarDeck 新客户端仅协商 logs_v2，单行最多 12 KiB UTF-8、每包 1..8 行且完整 JSON 最多 16 KiB；按实际编码字节分包，不再把日志截到 256 字符或用 8KB 省略占位代替原文。旧客户端 logs_v1 仍被新网关兼容，但不限制新客户端的能力。

既有凭证/地址等隐私过滤继续执行，长度限制和隐私处理分开。普通缓冲及快速/详细/重启诊断选择器保留完整行；超过单行或转义后包上限时，手动上传拒绝并保留预览以供本地导出；后台有界缓冲对无法发送或溢出的整行累加 dropped，不伪造成功。原有采集窗口和行数预算仍明确有效，不宣称采集了系统全部历史。

客户端只有收到 v2、source、batch_id、accepted_lines 全部匹配的 ACK 才计成功。连接失败时，App 在当前进程缓冲中保留原批次 ID/顺序用于重传；这是进程内队列，未新增跨应用重启的磁盘队列。系统日志仍需要重新预览与明确确认。服务端 v2 原子提交批次、fsync 后 ACK；保存摘要和行序号，重启后同批同内容幂等、同 ID 异内容拒绝。七天保留期与车辆隔离不变。

本候选沿用 E5 详细诊断功能线与 L3 隔离门禁；不改 CarPlay、音频、蓝牙、触摸、虚拟屏，也不自动修改稳定分支或正式 latest。服务端协议联调与客户端 Actions/签名发布/手机实测分别记录；本文件不代表 APK 已发布或手机已升级。

发布签名实验 APK 后的验收清单（当前均未测）：

1. 核对精确源 SHA、E5 包名、固定证书、递增 versionCode 和恢复包；保留已有日志与授权，不卸载清数据。
2. 主动启用 Gateway，发送含中文/emoji/引号的长行；服务器逐字回读应一致，字符数超过 256 不丢尾。
3. 手动预览并确认两条约 8 KiB 系统日志；应按字节拆包，确认数等于总数。12 KiB/JSON 单包超限应明确失败并可本地导出。
4. 断网/恢复或错误 ACK：原批次不误计成功，同 ID/内容重传，服务端不重复记录。应用重启不宣称进程内队列持久化。
5. 软件/系统日志、车辆关联、时间与凭据过滤、关闭上传及原有连接/触摸/视频回归；失败保留脱敏时间和步骤，经独立版本恢复，不强行降级覆盖。
